# @dsh-external/dsh-emoji

给 DSH 装一个**自己的表情包库**：导入图片，在设置页里管理，让 Agent 在回复中直接发出来，并且**随时按像素宽度调大调小**。

不依赖 VCPToolBox，也不依赖任何外部图床——库就在本机 `~/.dsh/emoji`。

---

## 装了什么

| 半 | 文件 | 干什么 |
|---|---|---|
| 宿主 | `lib/index.js` | 认领 `/api/dsh-emoji/*` 路由；注册 `emoji` 工具（含 `packs` / `use` 切包） |
| 宿主 | `lib/routes.js` | 12 条 HTTP 路由（列表 / 包列表 / 切包 / 出图 / 原图 / 导入 / 扫描 / 删除 / 配置 / 清缓存 / 健康 / 诊断） |
| 宿主 | `lib/store.js` | 库的落盘层：packs/<id> / cache/<id> / .trash / 配置文件 |
| 宿主 | `lib/imagecodec.js` | PNG·JPEG 解码、面积平均与双线性重采样、编码 |
| 宿主 | `lib/fence.js` | 回环信任围栏与请求体读取 |
| 浏览器 | `lib/client.js` | 「设置 → 表情包」面板；`:名字:` 速记渲染器 |

依赖只有 `pngjs` 与 `jpeg-js`，**两者都是零传递依赖的纯 JS 库**。刻意不用 sharp（原生模块要匹配 Electron ABI）与 jimp（27 个传递依赖）。

## 库长什么样

```
~/.dsh/emoji/
├── packs/                       ← 每一套表情包一个目录，可并存任意多套
│   ├── deepseek/
│   │   ├── pack.json            ← 显示名与建立时间（缺了就用目录名兜底）
│   │   └── images/              ← 这套的唯一真源。删了才是真丢
│   │       ├── 开心.png
│   │       └── 无语.jpg
│   └── feiyu/
│       ├── pack.json
│       └── images/…
├── cache/<包 id>/               ← 缩放产物，纯派生，可随时整目录清空重建
│   └── 开心@150.png
├── .trash/                      ← 删除落地处，可人工捞回
└── emoji.config.json            ← 宽度档位、扫描目录与当前生效的包（activePack）
```

三条边界是有意的：`cache/` 与 `images/` 分成两棵树，主人的原图任何时候都不该被缩放逻辑覆盖或清理；`images/` 按包分，**切包只改 `activePack` 这一个指针、不动任何字节**；`cache/` 也按包分，否则两套里同名的图会互相串味（`cache/` 的前一层是包 id 正是为此）。

库根可用环境变量 `DSH_EMOJI_HOME` 覆盖，或在插件配置里写 `home`。

### 多套表情包怎么切

- **切**：设置页顶部的「表情包套」下拉，或 Agent 侧的 `emoji packs` / `emoji use`。切换就是往配置里写一个 id，**零拷贝、零重建、立即生效**（路由每次请求都重新解析当前套，不需要重启）。
- **名字**：两套常有大半同名（同一个角色的不同画法），切过去就是同一张脸的另一个版本；只有一套里有的名字，切走后会 404（速记会原样保留成文本——可见的失败，不猜）。
- **旧布局**：`packs/` 为空而库根还有一个 `images/` 时，首次解析会把它**就地收编**成一套（`rename` 同盘搬移，只动图片）。收编之后库根不再有 `images/`。

## 用起来

### Agent 侧：`emoji` 工具

| 命令 | 作用 |
|---|---|
| `list` | 列出**当前这套**的全部表情包（名字 / 尺寸 / 体积 / 是否可缩放） |
| `search` | 按关键词模糊检索（`query`） |
| `send` | 发一张（`name` 支持模糊匹配），返回可直接粘贴的 Markdown |
| `random` | 随机发若干张（`count`，最多 6） |
| `packs` | 列出所有可切换的表情包套（当前生效的带 `*`） |
| `use` | 切到某一套（`pack`：id 或显示名），只改指针不动图片 |

`width` 是显示宽度（像素），默认 **150**，任意 4–2048 都成立。

`send` / `random` 的返回值就是**可直接嵌进回复正文的 Markdown 图片**——原样整行粘贴即可，不要改写 URL，也不要用代码块包住它，否则不会渲染成图：

```
![开心](http://127.0.0.1:19387/api/dsh-emoji/image?name=%E5%BC%80%E5%BF%83&w=150)
```

名字有歧义时（`name` 命中多张）工具会退回候选清单，而不是替你猜。

### 速记：正文里直接写 `:名字:`

浏览器半会在渲染后的 DOM 里把速记替换成 `<img>`，**不需要调工具、不需要 URL**：

```
:开心:          ← 默认 150px 宽
:开心@40:       ← 指定 40px 宽（行内小图）
```

- 名字对着**活库**精确匹配（`list` 端点，每分钟自动刷新；设置页切包会广播 `dsh-emoji:pack-changed`，名单立即重取）——库里没有的写法**原样保留**，没被替换本身就是可见的失败信号，不会猜
- 出图 URL 不带包 id（`?name=…&w=…`），所以**切包后已画在页面上的图刷新一下就会换成新那套的脸**；不刷新则维持现状，不会突然破图
- `@_@` 这类名字本身带 `@`：全名命中优先，`:@_@@40:` = `@_@` 以 40px 显示
- 宽度与工具同界（4–2048），越界按未命中处理、保持原文
- 代码块 / 行内代码 / 输入框 / 可编辑区域里的写法**不会被替换**
- 注入的是真实 DOM `<img>`，不走 markdown 渲染管线，因此不受宿主 `imageSource` 只放行 http/https 的约束
- **急停开关**：浏览器控制台执行 `localStorage.setItem('dsh.emoji.shorthand','off')` 后刷新页面，速记整体停用

已知边界：替换直接作用于 React 管理的 DOM。正常路径（DOM 攒到安静 400ms 或最多 2.5s 才动手、扫过的文本节点记入 WeakSet、React 重建子树后自然重扫）下安全；若某条消息被编辑或主题切换触发 React 就地复用已被替换的节点，理论上可能让该条消息渲染报错——刷新页面即恢复。这是「工具回执粘贴 Markdown」路线没有的风险，换来的是零工具调用、零 URL 编码、名单永不过期。

**真浏览器回归**：`node test/shortcut-browser/serve.cjs 8931`，然后开

- `http://127.0.0.1:8931/?noise=0` 静态页面
- `http://127.0.0.1:8931/?noise=1` 每 100ms 变更一次 DOM 的干扰源

页面把结论写进 `document.title` 与 `#result`（`PASS`/`FAIL` + 明细 JSON）。这个试验台抓出过两个 Node 侧测不到的缺陷：**遍历途中 replaceChild 会让 TreeWalker 停在原地**（整棵子树只替换第一处），以及**「每次变更重置定时器」的防抖会被常驻动画饿死**（flush 永不执行，一张图都不换且不报错）。另一条真机教训已写进注释：`ctx.effect(callback)` 要求回调**返回** teardown，在回调里直接拆卸会导致挂载瞬间自拆注册。

### 主人侧：设置 → 表情包

- **切包**：顶部的「表情包套」下拉（显示名 + 每套张数）；切换只动指针，画廊、速记与 Agent 侧立即跟着换
- **导入图片**：多选文件，逐个入库；重名自动加 `-2` 后缀，不覆盖
- **重新扫描**：把配置的扫描目录里的图片批量导入（幂等，已在库中的跳过）
- **清空缩放缓存**：只删**当前那套**的 `cache/<包 id>/`，原图不受影响
- **按名字筛选**、**预览宽度**调节
- 每张卡片显示尺寸 / 体积 / 格式 / 是否可缩放，可**删除**（进 `.trash`）
- **宽度档位**与**扫描目录**可编辑后「应用」（不会顺手把当前包重置掉）

## 尺寸是怎么调的

DSH 的 markdown 渲染器给 `<img>` 的样式是 `width: auto; max-width: 100%`——**图片按自身像素宽度显示，markdown 语法里没有任何办法指定尺寸**（这条是读 `dsh-client-ui-primitives` 的 `renderImage` 确认的，不是猜的）。

所以尺寸必须在服务端解决。本插件的做法是：**URL 带 `?w=`，路由里现算、落缓存**。

```
GET /api/dsh-emoji/image?name=开心&w=20     → 20×20
GET /api/dsh-emoji/image?name=开心&w=150    → 150×150
GET /api/dsh-emoji/image?name=开心&w=300    → 300×300
```

与「预生成固定档位」的差别：**任意宽度都可用**，且不必为没人看过的档位占磁盘；代价是首次请求多几十毫秒。第二次同宽度请求直接命中 `cache/`，字节完全一致。

缩小时用**面积平均**（下采样的正确做法，不会像最近邻那样丢线条），放大时用**双线性**；两者都按 alpha 做预乘加权，否则透明边缘缩放后会渗出黑边——表情包大量是透明 PNG，这一步不做会非常明显。JPEG 源继续输出 JPEG（转 PNG 会让照片型表情包体积翻几倍）。

宽度档位（默认 `20 / 28 / 40 / 150`）只是**给 Agent 的推荐值**，不是硬约束。

## 安全边界

读端点（列表 / 出图 / 原图 / 健康 / 诊断）只认**两档回环判据**——socket 远端地址落在 `127/8` 或 `::1`（**权威判据**；`X-Forwarded-For` 永不采信），外加 `Host` 头同样是回环字面量（挡 DNS rebinding）。socket 回环是硬约束：外部机器根本连不上；出图走 `<img>` 的 no-cors 加载，跨源也读不到像素，所以读端点不需要、也**不能**再查浏览器同源标记。

这条是被「图片无法预览」逼出来的：GUI 以 localhost 或 Electron 的 `file://` 提供界面时，自家 `<img>` 从 `127.0.0.1` 取图必然带 `sec-fetch-site: cross-site`，浏览器同源标记一查就把自家人 403 掉。围栏的第一版正是这么写的，第二版才拆成两档。

写路由（导入 / 扫描 / 删除 / 配置 / 清缓存 / 切包）会真实改动磁盘，保留**三重严格**：两档回环之上再加浏览器同源标记——`sec-fetch-site` 不得为 `cross-site`，`Origin` 若存在必须同源。

围栏每次拒绝都会进**环形缓冲**（最多 24 条，记时间、方法、URL、档位、远端与关键请求头），`GET /api/dsh-emoji/diag` 直接回放。再误伤时一次请求就能看到是哪一档拦的、对方实际带了什么头，不必重启靠猜。

所有名字经 `normalizeName` + `resolveImage` 收敛到**当前那套** `packs/<包 id>/images/` 内的绝对路径并做前缀校验，这是路径穿越的唯一闸口（`../../config.env` 已实测被拒）。包 id 另有一道 `isPackId`（禁分隔符 / 空白 / 控制字符 / 点开头），它同时是目录名与缓存路径的一段。导入时校验文件头能否读出宽高——伪扩展名的文本文件会被拒收，而不是入库成坏图。

```bash
npm test          # 三条一起跑
```

| 命令 | 覆盖 | 规模 |
|---|---|---|
| `npm run selftest` | 编解码、缩放比例与像素、库落盘、路径穿越、拒收伪图、缓存、配置；多套包解析 / 切包指针 / 缓存按包隔离 / 旧布局就地收编 | 77 项 |
| `npm run e2e` | mock 宿主 → 真挂 HTTP → 工具产出 Markdown → 真请求 URL → 解码验证宽度；含围栏/穿越/方法守卫/参数校验；另锁两档围栏语义与 diag 回放；两套包同名不同图的像素级比对与切包端点 | 72 项 |
| `npm run client` | mock `__ModuleLoader__` 走真实加载路径、两个槽位注册、effect 返回 teardown 的契约、SSR 渲染、速记解析语义、切包器与广播监听、API 相对路径 | 49 项 |

三者都在临时目录里跑（`DSH_EMOJI_HOME`），**不碰主人的真实库**。

另有一条**真浏览器**回归（需要 Chromium，故不进 `npm test`）：`npm run test:browser` 起试验台，用 `http://127.0.0.1:8931/?noise=0`（静态）与 `?noise=1`（每 100ms 变更 DOM 的干扰源）两个工况验速记渲染，结论写在 `document.title`。它专门覆盖 Node 侧测不到的层：MutationObserver 时序、活 DOM 遍历、常驻变更下的调度饥饿。上线首轮的两个缺陷都是它抓出来的。

`e2e` 的意义在于：宿主插件要重启 App 才装载，但「Agent 发出去的那条 Markdown，浏览器点开能不能按指定宽度出图」不该等到重启后靠肉眼判断。

## 已知边界

- **GIF / BMP / WebP 不支持缩放**，请求带 `w` 时直出原图（`list` 会标 `scalable: false`）。动图缩放需要逐帧处理，本轮不做。速记与工具仍会给 `<img>` 打上宽度属性，所以显示宽度是对的，省掉的只是服务端的重编码。
- **两套包的名字并不完全重合**：同名的切过去换脸，只在某一套里有的名字切走后就是 404（速记保持原文）。要按当前生效的套查名，用 `emoji list` / `search`。
- **出图 URL 不带包 id**，因此切包后历史消息里的图刷新一下会一起换成新那套（这是刻意的：同一个角色的另一版画法，不是缓存串味）。要两套并存显示，只能先截图或另存。
- **表情包清单不会自动进系统提示**：Agent 需要主动调 `emoji list` / `search` 才知道有哪些可用（本机是在 `~/.dsh/AGENTS.md` 的 `[Emoji]` 段里维护了一份两套并集速查表）。
- **`.trash` 只增不清理**：删除是可恢复的，但回收站没有自动过期策略，需要人工清。
- **预览宽度影响画廊缩略图**：设置页里调它会为每张图生成对应宽度的缓存文件。库很大时建议用较小的预览宽度。
- 首次请求某宽度需现算（几十毫秒），之后命中缓存。
